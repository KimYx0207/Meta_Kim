# Repository-managed Graphify lifecycle

Meta_Kim can opt a repository into a local Graphify lifecycle that keeps Graphify as the producer and adds a repository-owned manager around publication. The manager is intentionally POSIX-only for this first integration and covers Git lifecycle events: `post-commit`, `post-checkout`, `post-merge`, and `post-rewrite`. It does not promise file-save or uncommitted autosave refresh.

The lifecycle is opt-in. A repository must already have a `graphify-out/graph.json`; `managed-install` writes `.git/graphify/config.json` and rewrites Graphify-owned Git hook blocks to dispatch through `scripts/graphify-managed.py`. Custom bytes before and after the managed marker block are preserved. Future Graphify installs may rewrite the native hook block, so setup and CLI update paths re-run the manager install when an existing managed config is present.

Managed paths must be plain directories in the main checkout, including `.git`, the graph root, candidates, previous bundles, and their control-path parents. Linked or separate Git directories are not adopted. Unknown links in seed/cache trees fail closed. Cleanup and directory promotion use held directory descriptors with no-follow parent traversal; recursive cleanup requires Python's symlink-attack-resistant `rmtree` implementation. A refused refresh preserves the current graph and does not follow a link to clean an external cache.

This hardening targets the reported link-based cleanup and ownership failures. It is not a general filesystem sandbox: other install/configuration writes remain path-based, and the manager does not claim that every file read or write is safe against an adversary concurrently replacing all filesystem paths.

Shared `core.hooksPath` is supported only while its Graphify registration belongs to this repository. Installation takes a shared `.meta-kim-graphify-install.lock`, verifies all four event blocks before writing repository runtime state, and refuses another repository's registration without replacing its hook bytes. Existing native Graphify blocks in the repository's own `.git/hooks` may still be upgraded. This version does not add a multi-repository hook dispatcher.

Curated hyperedge members use the same verified legacy-ID mapping as ordinary edge endpoints. Relationship attributes and member-field format are preserved, while missing, ambiguous, collapsed, or dangling member mappings fail closed. Repeating a native refresh must keep the already rebound relationship unchanged.

Normal `rebuild` routes through the manager when `.git/graphify/config.json` exists. `rebuild --verified-local-update` remains the strict verified-local path and bypasses the manager. Setup preserves the same distinction: if a managed config exists, the final Graphify refresh calls the manager `run` action instead of falling back to raw `python -m graphify update .`.

Managed install also keeps the same-entry Git alias `meta-graphify` pointed at the same manager, so generated guidance inside the AGENTS `## graphify` section can call `git meta-graphify run` without bypassing the lifecycle. The manager repair must run after all platform skill installers because native `codex install` and related platform installers can rewrite the AGENTS graphify section and restore raw `graphify update` guidance.

The producer contract is local AST plus retained known knowledge, with no model calls. The manager coalesces concurrent requests to the latest observed source snapshot rather than storing a permanent event archive. It keeps a finite lifecycle footprint: fixed `current` at `graphify-out`, one previous published graph bundle at `.git/graphify/previous`, one candidate bundle at `.git/graphify/candidate` while work is active, worker logs at 2 MiB with three rotated backups, and AST cache pruning after 30 days or above 1 GiB. Install materializes only `graphify-managed.py` and `graphify-managed-producer.py` into `.git/graphify/runtime` so hooks and the Git alias survive source package or npx cache removal. Explicit `.graphifyignore` matches retire those sources from managed preservation before historical Gitignored-source protection is considered. Unknown Graphify output records are retained unless they are Graphify-owned transient work files or superseded native dated backups. It must preserve existing managed memory and reflections material when it rewrites only the Graphify-owned section of generated instructions. Release checks should treat `managed-status` as repository-local evidence only and continue to verify `graphify-out` artifacts before publication.

`npm run meta:graphify:test` is the source-checkout regression entrypoint for the managed Python lifecycle. It uses the repository Python resolver, skips clearly when optional Graphify 0.9.56 is unavailable, and runs the manager and producer Python unittest files when that version is present.
