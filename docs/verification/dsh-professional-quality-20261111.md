# DSH、专业交付与连续性：本轮验证记录

日期：2026-11-11（Asia/Shanghai）。基线为 `b8599184b9624fbb1cee0feeccaffa0d8fed76d2`。本轮提交源码和回归修复，合集与 npm 版本仍沿用各自的已发布版本。

## 本轮具体改了什么

1. **接上 DSH 的实际安装生命周期。** `meta-kim dsh` 支持安装、更新、检查和卸载，全局 profile 与项目 patch 分开管理。完整方法、合同、执行源码按无损分段提供，官方读取器与结果裁剪器都参与验证。
2. **补齐真正要用的资料。** DSH 的 source 包提供入口明确要求的运行时矩阵、系统矩阵、能力注册和宿主配置。12 个公开配置逐项选择，额外的机器私有配置不随包导出。Kim Service 的图片和 ZCode 的专业组件、资料树也完成了对应闭包修复。
3. **让专业标准进入执行上下文。** 工作者收到所选能力的通过条件、拒收条件、检查方法、必要证据和阻断规则。标准初态为 `not_observed`，工作者自报成功仍等待独立核验。合法的只读 `Grep` / `Glob` 能力声明得到正确识别。
4. **修复准备阶段到任务设计的正常续做。** 在尚无工作者、DAG 或执行记录的已验证准备态，允许本次 Thinking 添加任务验收分配；用户任务、意图、设计需求和配对材料的身份仍须一致。已经绑定的分配或实际执行记录继续按完整指纹校验，不能通过这个过渡更换验收对象。
5. **恢复验证链的可信度。** 测试调用按现行 prepare → Fetch → Thinking → resume 协议迁移。用户可见报告从真实的 verification 与 summary 判断完成，不再从运行时配置通过推断产品完成。移除主 runner 中提前返回之后的不可达旧报告代码。
6. **大份计算材料不阻塞宿主。** Node 到 Python 的输入改为异步写入并明确发送 EOF，保留 10 秒期限、标准输出与错误合计 4 MiB 上限，以及来源、权限、任务和回执检查。超限、超时与不完整输入不能被认作成果；等待进程关闭后再清理本次来源快照。

## 独立审查结论

代码审查复现了 DSH 和 ZCode 的缺失资源问题，修复后分别验证完整源层级、文件原字节、资源分段和私有配置排除。Service 的经营财务、库存供应与数据质量算例另作独立复算，未发现需继续修改的实质错误。

对测试迁移的检查覆盖了主 runner、诊断入口、宿主推理夹具及发生明显变化的测试。无真实执行时仍保持 `partial` / `actualWorkerExecution=false` / `publicReady=false`；合成选择明确标注，错误身份和不匹配输入继续拒绝。准备态例外只允许被验证的空准备状态向本次任务设计前进。

异步计算另经独立审查并复跑 6 项真实子进程检查。原 10 秒期限和合计 4 MiB 限制没有放宽；`exit 2 + EPIPE` 只允许进入后续完整 `invalid_input` 回执验证，不直接构成成功。macOS CI 中的大输入同步管道超时是改造动因；未把相似的 Node 上游问题认作已经证明的唯一根因。Windows 探针中的 CRLF 差异改为写固定字节，业务计算和原精确断言不变。

## 研究如何落到改动

- [DSH 官方固定版本](https://github.com/deepseek-ai/deepseek-harness/tree/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159)：按真实 Skill、profile、patch 与 MCP 接口实现，使用同版本读取器和裁剪器验证。
- [Spec Kit converge](https://github.com/github/spec-kit/blob/main/templates/commands/converge.md)：对照规格、计划与实际实现找缺项，保留已经满足的工作。本轮据此核对两层设计、专业资料与真正打包出来的文件。
- [LangGraph 容错](https://docs.langchain.com/oss/javascript/langgraph/fault-tolerance)：恢复要区分已完成、可重试和外部结果未知。本轮保留现有耐久内核，以实际重开和已完成任务不重跑验证连续性。
- [Node 子进程文档](https://nodejs.org/api/child_process.html)：异步进程、有限管道和明确结束输入用于实际计算传输；原有来源与业务回执判断仍由调用方执行，不把管道改造当作额外沙箱。
- 专业包的方法、领域资料、正反例和每项检查标准由 [Kim Service 的研究记录](https://github.com/KimYx0207/Kim_Service/blob/main/docs/research/professional-expansion-2026-11-11.md)统一记录，采用范围和不适用条件可回查。
