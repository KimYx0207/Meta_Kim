# Governance method loader

Read `method.json`, then its `partsIndex`, every listed index page, and every primary-method part in order. Part/page paths are relative to the index directory. The complete canonical role contains knowledge, inputs, boundaries, actions, artifacts, review criteria and escalation; this loader is not the expert definition itself. Resolve links in parts against the original source file's directory. Related canonical files live in `../meta-theory/source/`. Markdown, JSON, YAML, TOML, text, CSV and supported text-source files have sibling `<filename>.dsh-parts/index.json` views with bounded length, line count and line length. Read all pages/parts of required contracts or selected executable source reviews, including outputChecks, acceptance rules and rejection code; never infer omitted content or read a large resource as one truncated result. Run unchanged original scripts, never their split views.

Load `meta-theory` and its DSH runtime reference for the governing workflow. Preserve this role's canonical governance boundary; do not turn a governance owner into a coding, design, marketing or other business worker.

For a bounded delegated governance task, use only the actual DSH `subagent` capability discovered in the active host. Give the child this skill name, the complete method paths, the task inputs, scope, evidence, expected output and acceptance owner. Inherit the current preset rather than inventing a preset with a role name; a native Skill does not register a custom native agent. The returned child identifier is a start receipt, so wait for the actual terminal result before accepting its work. No method or prompt grants tools, credentials, approval or release authority.
